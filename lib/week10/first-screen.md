# 📱 첫 화면 구상 및 확인 기록

## 1. 첫 화면 구상 (UI 및 조작)
본 화면은 PRD의 핵심 요구사항(REQ-1, 2, 3)을 충족하도록 정보와 조작을 배치함.
* **정보 (Information):** 
  * 상단 앱 타이틀 영역 ("뭐 먹지?")
  * 하단 결과 출력 영역 ("오늘의 추천 메뉴는...", "💡 꿀조합/레시피: ...") ➔ **[REQ-3 연결]**
* **조작 (Controls):** 
  * '점심' / '저녁' 선택 버튼 그룹 ➔ **[REQ-1 연결]**
  * '배달' / '집밥' 선택 버튼 그룹 ➔ **[REQ-1 연결]**
  * '메뉴 추천받기' 실행 버튼 ➔ **[REQ-2 연결]**
* **반응 (Reactions):** 
  * 조작부 버튼 터치 시 활성화된 버튼의 색상이 반전됨 (`setState`).
  * 실행 버튼 클릭 시 하단 정보 영역의 텍스트가 선택된 조건의 데이터로 즉시 교체됨.

## 2. 첫 화면 구현 요약
* **기술 환경:** Flutter (`flutter create my_first_app`)
* **핵심 구현 코드 위치:** `lib/main.dart`의 `StatefulWidget` 내부 
* **데이터 분리:** `lib/data.dart`를 생성하여 외부 연동(API) 없이 커스텀 `Menu` 객체 리스트(하드코딩) 구현 완료. 예시 데이터와 실제 외부 저장을 명확히 구분하여 이번 주차는 로컬 예시 데이터만 사용.

## 3. 완료 기준별 확인 기록 (테스트 결과)
* **[AC-1] 정상 동작 확인 (직접 실행)**
  * **기대 결과:** 저녁/집밥 선택 후 버튼 클릭 시, 볶음밥 등 집밥 메뉴 1개와 4줄 레시피가 화면에 출력됨.
  * **실제 결과:** (통과) 에뮬레이터에서 터치 시 즉각적으로 상태가 변환되며 `Text` 위젯에 정상적으로 메뉴와 레시피가 렌더링 됨을 직접 눈으로 확인.
* **[AC-2] 예외 처리 확인 (직접 실행)**
  * **기대 결과:** 점심만 누르고 방식(배달/집밥)을 누르지 않은 상태로 추천 버튼 클릭 시, 하단 스낵바에 "모든 조건을 선택해주세요" 노출.
  * **실제 결과:** (통과) 조건문(`if`) 분기 처리를 통해 버튼 클릭 이벤트를 막고 `ScaffoldMessenger`로 스낵바 팝업이 정상 작동함 확인.
* **정적 분석 (분석/검사)**
  * `flutter analyze` 실행 결과, No issues found. (통과)

## 4. 미완료, 미실행 및 11주차 다음 작업
* **미완료 사항:** 실제 룰렛이 돌아가는 듯한 시각적 애니메이션 딜레이(`Future.delayed`) 처리는 이번 첫 화면 기능 검증 단계에서 제외(미실행)함. 
* **아직 확인하지 않은 가정:** "진짜 이 앱이 결정을 빠르게 해주는가?"는 개발 중이므로 앱 완성 후 실제 본인이 3일 이상 사용해보며 검증할 예정임.
* **11주차 목표:** 앱 디자인 폴리싱(테마 색상, 폰트 적용), 추천받기 클릭 시 약간의 로딩 인디케이터 추가, 메뉴 리스트 데이터 볼륨 확대(각 조건별 최소 5개 이상).
