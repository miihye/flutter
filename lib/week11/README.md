### 1. 이번에 구현하거나 수정한 사용자 행동
이번 11주차 실습에서는 기존 10주차 기획(PRD)에서 정의한 '핵심 가치(2차 고민 차단)'를 모바일 화면에 시각적으로 고도화하고, 12주차 발표 시연을 위한 UX 흐름을 개선했습니다.

* **화면 전환 및 집중도 강화:** 기존에는 한 화면에 조건 버튼과 결과가 모두 노출되었으나, 추천 버튼 클릭 시 조건 UI가 사라지고 결과 카드만 전체 화면으로 노출되도록(`_hasSearched` 상태 활용) 수정하여 정보 집중도를 높였습니다.
* **상태 초기화 및 재추천:** 결과 화면 하단에 `[처음으로]`, `[다른 메뉴]` 버튼을 배치해, 언제든 조건을 리셋하거나 즉시 다른 메뉴를 재추천받을 수 있는 사용자 행동을 추가했습니다.
* **데이터 시각화 (2차 고민 차단 핵심 기능):**
  * **집밥:** 단순 줄글로 나오던 레시피를 파싱하여, '준비할 재료'와 '소스 및 양념'을 서로 다른 색상의 태그(`Chip` 위젯)로 렌더링했습니다.
  * **배달:** 메뉴 이름만 나오던 것을 넘어, 어울리는 '추천 사이드 꿀조합'을 독립된 카드 리스트(`Container`)로 시각화하여 추가 주문의 고민을 차단했습니다.
* **12주차 발표용 로드맵 UI 시각화:** 추후 구현할 데이터 기록 및 공유를 위해, 앱바에 '달력 아이콘'과 결과 화면에 `[식사 기록]`, `[결과 공유]` 버튼을 배치하고 스낵바 피드백을 연결했습니다.

### 2. 필요한 상태·데이터와 항상 지켜야 할 규칙
* **상태 (State)**
  * `_selectedTime`, `_selectedCategory` (List<bool>): 점심/저녁, 배달/집밥 선택 여부를 유지하는 상태.
  * `_hasSearched` (bool): 조건 뷰와 결과 뷰의 화면 전환을 통제하는 플래그.
  * `_recommendedMenu` (MenuData?): 추출된 단일 메뉴 객체를 담는 상태.
* **데이터 (Data)**
  * `_menuList`: 하드코딩된 총 8개의 `MenuData` 객체. 문자열 파싱 로직을 위해 '재료:', '소스:' 등의 특정 접두사를 반드시 포함하도록 구성했습니다.
* **항상 지켜야 할 규칙 (Invariants)**
  * **방어 로직:** 추천 버튼(`_recommendMenu`) 실행 시, 2가지 조건(시간대, 식사 방식)이 모두 선택되지 않았다면 알고리즘이 절대 동작하지 않아야 합니다.
  * **UI 분기 규칙:** 객체의 `category` 값이 '집밥'인지 '배달'인지에 따라 데이터 렌더링 방식(`split` 후 `Chip` 생성 vs 배열화 후 `Card` 생성)이 정확히 나뉘어야 합니다.

### 3. 입력·기대 결과·실제 결과를 적은 확인 기록
* **[AC-1] 예외 처리 방어 테스트**
  * **입력:** 조건 중 하나(예: 식사 방식)를 누르지 않고 `[메뉴 추천받기]` 클릭
  * **기대 결과:** 상태 변화 없이 하단에 "시간대와 식사 방식을 모두 선택해주세요!" 스낵바 노출
  * **실제 결과:** (통과) 분기문에 의해 상태 변환(`setState`)이 차단되고 경고 스낵바가 팝업됨.
* **[AC-2] 초기화 및 상태 롤백 테스트**
  * **입력:** 결과 화면에서 `[처음으로]` 버튼 클릭
  * **기대 결과:** `_hasSearched`가 `false`로 변하며 첫 화면으로 돌아가고, 버튼 색상이 모두 비활성화됨.
  * **실제 결과:** (통과) `_resetSelection` 함수가 정상 작동하여 첫 진입 시점과 동일하게 복귀함.
* **[AC-3] 데이터 파싱 및 시각화 테스트**
  * **입력:** 집밥(예: 버터 간장계란밥) 결과 도출
  * **기대 결과:** `infoContent`의 줄글이 쉼표(,)를 기준으로 파싱되어 주황색, 빨간색 `Chip` 위젯들로 변환 노출.
  * **실제 결과:** (통과) 정규화된 하드코딩 데이터를 기반으로 UI 코드단에서 정상 `split`되어 태그 형태로 렌더링 됨.
